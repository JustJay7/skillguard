# SkillGuard security review core

## Current product flow — October 23

The main app reviews whether to admit a pending skill. Receipt extraction is the isolated test workload, not the product's primary action. Every automatically detected native pending write receives a security-required marker; the older actual-agent diagnostic cannot bypass that gate.

1. Native Hermes pauses the exact guide/parser update. SkillGuard snapshots it and compares its observed envelope with the installed baseline.
2. Native NVIDIA SkillEvaluator checks source and Harbor/OpenShell executes twelve regression cases. Source mismatch, incomplete scanning, failed functionality or extra private-file attempts prevents approval.
3. SkillEvaluator's native generator produces four annotation probes under trusted generation framing. The native response parser is retained. Required coverage includes fake private-file authorization, amount poisoning, a fake system message and an unrelated control. Fixture checks reject missing coverage before any agent call. These small generated cases are not an independently curated benchmark.
4. Harbor's actual Terminus agent reads the selected guide and receipt, chooses its tools and writes an answer. OpenShell supplies isolation and policy enforcement. An independent unchanged receipt contract grades the original purchase; the annotation cannot supply replacement values. Each trial has a durable single-use claim, at most six requests, 2,000 output tokens and thinking disabled. Positive native guide/input/output evidence and completion confirmation are required. Issued commands, output, partial Sysdig metadata, private-file witnesses and costs are retained. A fake-key preflight checks wiring without earning model credit.
5. Nemotron receives source/regression evidence, generated inputs, actual recorded agent commands/outcomes, policy and explicit limitations. It returns a schema-checked recommendation referencing supplied evidence IDs. Deterministic checks still block failed behavior even if the model says allow. Incomplete evidence stays held. The model cannot widen permissions.
6. Declared receipt directories and explicit runtime prerequisites compile into the bounded OpenShell policy. Compilation must exactly match the native policy admitted for the tests. The app shows permissions and evidence before approval. This is one supported runtime profile, not arbitrary-skill least-privilege synthesis.
7. A restricted pass enables an explicit operator decision. When all native evidence is complete and passing but Nemotron recommends hold, a separate warning acknowledgment and 20–1000 character operator reason can authorize an exception. Its manifest says `operator_approved_hold`, retains both model recommendations and binds the exact review hash. It is not a security pass. Failed tests, unsafe actions, incomplete probes, changed source/policy and prior blocked security evidence cannot use this route. New evidence invalidates the prior exception for execution and rollback. Installation verifies exact source/evidence/revision and creates a separate version profile. Every installed-manifest field must match its acknowledged operator-approval event. Reject preserves the archive. The known-repair route rejects the unsafe update, stages exact V8 and runs a new review; it does not claim generic autonomous repair. Rollback selects a preserved, still-valid approved version.

A provider-incomplete trial remains incomplete and charged. Explicit infrastructure recovery can reverify and reuse completed probes, retain the failed claim, and execute only remaining checks with unchanged skill/input/grader bytes. The recovery is disclosed to Nemotron and is not a fresh benchmark. No unknown-cost hold is released without proof. The [short text reservation](text-request-bound.md) bounds new requests without changing historical costs or the $0.75 cap.

The native HTTPS readiness check runs in the trusted controller without credentials before live inference. It does not grant network access to the candidate workload. Public cloud sandbox access remains unavailable; the verified runtime is local native OpenShell. Browser visual QA remains unverified; API actions and native evidence are tested separately.

## Earlier receipt-workload lifecycle — October 22

The scope frozen on October 22 is one local receipt workflow. The application owns a learning profile, checked review archive and isolated installed-version profiles under `results/core/`. The user's default Hermes profile is not changed.

1. Native `skill_manage` stages a guide/parser creation or update under the skills write-approval gate. The app discovers pending writes, snapshots exact bytes and captures an installed baseline for updates.
2. Before execution, the pending payload is validated through pinned native Hermes in a disposable profile and compared with the captured source. NVIDIA SkillEvaluator runs complete Tier 1 checks. NVIDIA Harbor's Oracle executes the parser against twelve existing authored regression cases inside native OpenShell, and the native rich-to-numeric adapter supplies domain verification.
3. Native OpenShell admits the fixed policy, uses UID 1000 with zero effective capabilities, grants no external network or host-file mounts and keeps source/input read-only. An independent readable-by-Unix-permissions fake file must be denied. Image/container/policy, private-file controls, source identity, native output and stopped state are checked. Additional observed private-file denial attempts beyond the independent control block approval. Native Sysdig metadata includes setup/verifier activity; it is not complete or universally attributable to skill code. Full compressed captures remain in the dedicated VM; the core archive exports selected syscall metadata and its hashes, not the raw capture.
4. **Test actual agent** materializes the exact selected candidate in the existing native Harbor task, with the receipt in an explicitly untrusted input file. Before inference, the native controller checks that file's hash in the container. The new selected-guide protocol lets Nemotron choose its extraction tools and apply V8 itself, then save/read back its answer and confirm native completion. The unchanged independent grader checks the answer. Native Sysdig must positively show the guide read before input and reread after input, receipt reads and answer writing during inference execution. Native discovery and post-agent collection cannot earn use credit. The older parser-based protocol retains its original guide/parser/input/output requirements. No old result is relabeled as the new protocol. The review archives provider requests/replies, costs, trajectory, collected source/input/output, native confinement and capture evidence. New app approvals require this exact review's agent pass, bound to current parser checks.
5. Approval requires an exact current review revision, current passing static/runtime checks, unchanged pending/source/policy and explicit acknowledgment of the restricted workspace. Rejection uses native `discard_pending` and keeps the archive. This does not change the earlier review's blocked unrestricted-activation verdict.
6. Native `apply_skill_pending`, the same primitive used by Hermes' approval handler, writes a separate version profile. Its exact resulting tree must match the review. A matching operator-approval event is required before a version can be selected. Only then does the app atomically update its installed-version pointer and remove the native pending write. A failed installation cannot replace the active pointer.
7. **Run installed agent · fictional receipt** checks the expected active version, immutable installed source, review and current agent eligibility. A new proposal binds the active version UUID and candidate. It starts a genuinely fresh existing native workflow rather than returning the review's cached answer. Each proposal has its own request identity and single-use durable claim; old claims cannot be reused. The fixed fictional task and selected skill are exported under the existing bounds. The latest installed-agent answer is displayed from the preserved review after refresh. The separate local parser utility verifies the installed tree and its approved review, then delegates execution to native Harbor/OpenShell. Typed text remains local. Ad-hoc parser output is schema-checked; it does not receive reference-value correctness credit. Rollback selects only a preserved, still-valid approved version with an unchanged policy and source. It switches the pointer and preserves both installations.

The UI uses same-origin CSRF-protected actions, bounded JSON bodies, revision checks and serialized jobs. Its state response cannot mix a completed operation with the prior installed version. Operations finish native cleanup before graceful server shutdown. Separate receipt workspaces serialize access to the shared native VM.

The verified run `core-flow-dc10aede` exercised native rejection, installed receipt use, tested update, installation, rollback and restored-version use. Its first installed version was created and independently exercised earlier in the same work session; the command explicitly identifies that reuse. The app-route verification is saved separately in `results/core-http-verification.json`.

The supported agent completed the learned-skill receipt in `receipt-agent-72fc12e8`, using six fresh requests. That result belongs to candidate `7d74003d...`, not the app's different authored example. The separate app-candidate run `receipt-agent-0bc8aa67` passed in five fresh requests, with a correct answer and native completion. Its event is bound to review `508b0554...` and its current parser/static checks. Historical failures remain failures. These are bounded authored task checks, not causal learning or general resistance evidence; unrestricted activation remains unavailable.
